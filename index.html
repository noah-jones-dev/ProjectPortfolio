About

I'm a Software QA Engineer who cares about the boring parts that make software trustworthy: repeatable tests, readable frameworks, and bug reports someone can actually act on.

My day-to-day is automated, manual, and API testing across web and mobile — Selenium, Playwright, and Appium, wired up with NUnit, XUnit, Pytest, and Behave. I care less about clever test code and more about frameworks the next person can pick up without a tour guide.

Outside of QA I build things for fun: cross-platform desktop tools, and indie games under NoJo Studios using Unreal Engine 5 and Unity. Game dev turns out to be a sneaky-good QA teacher — nothing finds your edge cases faster than handing a build to a player.

Web Automation — Behave BDD

Python · BDD

Python web automation built on Behave, following Behaviour-Driven Development practices so tests read like plain English.

  • Python
  • Behave
  • Gherkin
  • Selenium

What it does

Automates modern web applications using the Behave BDD framework, with scenarios written in Gherkin — Given / When / Then — so non-engineers can read and review the test suite.

Why it's interesting

BDD is where QA meets communication. Written well, the feature files double as living documentation; written badly, they're a slow way to write Selenium. This framework is structured to stay on the right side of that line.

Highlights

  • Gherkin scenarios readable by the whole team
  • Clean separation of steps, pages, and fixtures
  • Built to run seamlessly inside Visual Studio
  • Scalable structure for growing suites

Browser automation with Playwright and C#, using XUnit — the modern alternative to Selenium, with auto-waiting built in.

  • C#
  • Playwright
  • XUnit
  • .NET

What it does

Automates browser workflows efficiently using Playwright, paired with XUnit for structure and assertions.

Why it's interesting

Playwright's auto-waiting removes the single biggest source of flaky UI tests: hand-rolled sleeps. Building the same coverage on Playwright as on Selenium is a direct, practical comparison of the two approaches to stability.

Highlights

  • Auto-waiting instead of brittle explicit sleeps
  • Modern cross-browser engine coverage
  • XUnit structure with clean, maintainable code
